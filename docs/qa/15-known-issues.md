## BUG-04 — Белый экран после разговора с Соней (P0, исправлено)
- **Симптом (сообщил игрок):** после закрытия диалога Сони кнопкой «За работу» — белый экран, офис не рендерится; в консоли `TypeError: Cannot read properties of undefined (reading 'length')` + React «change in order of Hooks».
- **Причина:** при переносе доски в `OpenSpace.tsx` строка `useGameStore(s=>s.phase)==='free' && useSprintStore(s=>s.phase)` вызывала **второй хук условно** (короткое замыкание `&&`). На переходе meetPm→free число хуков в `OpenSpaceWhiteboard` менялось, сдвигая позицию идущего следом `useFrame` → повреждение подписки R3F → `undefined.length` и размонтирование всего React-дерева (белый экран). В исходном `MeetingRoom` тот же `&&` был, но без `useFrame` после него — поэтому только warning, без падения; мой `useFrame` превратил его в краш.
- **Фикс:** оба хука вызываются безусловно (`OpenSpace.tsx`): читаем `gamePhase` и `sprintPhase` отдельными вызовами, затем комбинируем. Проведён поиск по всему коду — других условных хуков (`&& useX(`, `?: useX(`) нет.
- **Проверка:** воспроизведён реальный путь (seed meetPm → подойти к Соне → «За работу») — до фикса белый экран + ошибка, после фикса `Спринт 1` виден, canvas жив, 0 ошибок. Добавлен E2E-регресс `e2e/pm-transition.spec.ts`, гоняющий именно этот переход.

## PERF-02 — Context Lost / долгая загрузка / лаги офиса (исправлено)
- **Симптом (сообщил игрок):** после разговора с Соней рендер офиса ломается, `THREE.WebGLRenderer: Context Lost`, офис долго не появляется и сильно лагает.
- **Причина:** character `idle.glb` содержали **4096² несжатые PNG-текстуры** (Kirill 46 МБ, cybersecurity 91 МБ; всего 362 МБ ассетов). В декодированном виде 4096²·RGBA ≈ 64 МБ на текстуру × ~40 текстур > 1 ГБ GPU-памяти → исчерпание видеопамяти и потеря контекста на интегрированных GPU (плюс Windows TDR на тяжёлых кадрах).
- **Фикс:**
  1. Все текстуры персонажей уменьшены до **1024²** (`scripts/optimize-character-textures.mjs`, `sharp` + `@gltf-transform`), формат сохранён (png/jpeg — без новых glTF-расширений), геометрия/анимации не тронуты. Ассеты **362 МБ → 61 МБ**; GPU-память текстур ~×16 меньше. Пайплайн `convert-character.mjs` обновлён, чтобы будущие ре-экспорты не возвращали 4K.
  2. `dpr` ограничен `[1, 1.5]` (было `[1, 2]`) — меньше нагрузка на GPU на HiDPI.
  3. Убран неиспользуемый `preserveDrawingBuffer` (лишняя память).
  4. Добавлен обработчик `webglcontextlost` (`preventDefault`) — контекст восстанавливается, а не остаётся чёрным навсегда.
- **Проверка:** headless-загрузка free-play с 3 NPC (Кирилл/Алина/Илья) — GLB парсятся, сцена монтируется, ошибок нет; 779 unit + build зелёные. Пиксельный рендер на реальном GPU подтверждает игрок (headless SwiftShader кадры не снимает — KI-06).

## Не выполнено в автоматическом прогоне (принятые пробелы верификации)

### KI-04 — ЗАКРЫТ
Браузерный E2E-набор добавлен и зелёный (см. выше). Клик-проход интро в E2E намеренно не включён: под software-рендером без GPU декодирование character-моделей кратковременно насыщает main-thread, из-за чего клики по интро-кнопкам ненадёжны (на реальном GPU декод <1s). Логика интро полностью покрыта `IntroOverlay.test.tsx`; в E2E интерактивность доказана кликом рестарта на game-over (frameloop там погашен → клики надёжны).

### KI-05 — Ручные проверки: soak, resolutions, live DeepSeek smoke, RUN-01–10 UI
- 30-минутный NPC soak, проверка UI на 1366×768/1920×1080/2560×1440, live DeepSeek smoke (≤1 запрос на NPC, без секретов в логе) и полные ручные RUN-01–10 через UI — **не исполнялись** в этом автоматическом прогоне; описаны протоколами.
- **Влияние:** визуальная/производительная полировка и «живое» качество ответов ИИ не подтверждены автоматически.

### KI-06 — Headless canvas-захват пуст в текущей среде
- **Severity:** P3 (инфраструктура верификации, не игра).
- **Симптом:** при снятии скриншота через SwiftShader canvas остаётся белым и в console видны `THREE.GLTFLoader: Couldn't load texture blob` (текстуры персонажей). Сцена при этом жива: рейкаст-клики попадают в объекты, HUD/оверлеи работают, NPC перемещаются между кадрами.
- **Влияние:** визуальная приёмка новой позиции whiteboard и стены выполнена функционально (рейкаст + панель + геометрические тесты), но кадр сцены в отчёт не снят. На реальном GPU в предыдущих итерациях сцена рендерилась корректно.
- **Workaround:** ручной визуальный прогон на реальном GPU (WB-10 в manual matrix).
