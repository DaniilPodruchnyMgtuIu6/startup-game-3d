# Feature 16 — Performance Report

## Среда и метод

- OS: Windows 10; Node v22.20.0; Vite 8.1.4; React 19; three r0.185; @react-three/fiber 9.
- Целевая машина игрока: ноутбук с интегрированным GPU (по симптомам).
- **Ограничение измерений (KI-06):** в CI-среде рендер идёт через headless SwiftShader (программный, без GPU). FPS, draw-call-время и heap там недостоверны и не отражают реальный GPU. Поэтому «до/после» здесь фиксируется по **детерминированным метрикам** (размеры ассетов, разрешения текстур/теней, число проходов рендера, размер бандла) и по **подтверждённому игроком эффекту**, а живое FPS-профилирование на реальном GPU остаётся отдельным пунктом.

## Первопричина, найденная и устранённая

Игрок сообщал: `THREE.WebGLRenderer: Context Lost`, долгая загрузка и сильные лаги офиса. Первопричина — **исчерпание видеопамяти** оверсайз-текстурами персонажей (4096² несжатые PNG в каждом `idle.glb`). После исправления (ниже) игрок подтвердил, что потеря контекста и белый экран ушли.

## Изменения производительности: до → после

| Область | До | После | Эффект |
|---|---|---|---|
| Character assets (всего) | **362 MB** | **64 MB** | −82% скачивания/декода |
| Крупнейший `idle.glb` (cybersecurity) | **89 MB** | **6 MB** | текстуры 4096² → 1024² |
| Текстуры персонажей | 4096² PNG, несжатые | ≤1024² (формат сохранён) | GPU-память текстур ≈ **×16 меньше** (4096²·RGBA ≈ 64 MB/текстуру → 1024² ≈ 4 MB) |
| GPU-память текстур (≈40 текстур, ~8 персонажей) | **> 1 ГБ** (переполнение integrated GPU → context loss) | **~100–150 MB** | устранение потери контекста |
| `dpr` (pixel ratio) | `[1, 2]` | `[1, 1.5]` | −~44% пикселей на HiDPI |
| Directional shadow map | 2048² | 1024² | −75% текселей теневого прохода |
| N8AO (ambient occlusion) | full-res, дефолт | `halfRes` + `quality: performance` | AO вдвое дешевле |
| Accent-споты (TrackLight) | `castShadow` (2 шт.) | без теней | −2 полноценных shadow-прохода/кадр |
| `preserveDrawingBuffer` | `true` | убран | меньше памяти, без лишнего копирования буфера |
| WebGL context-loss | не обрабатывался (чёрный экран навсегда) | `preventDefault` → восстановление | устойчивость |
| Idle-меню (интро/финалы) — *откат* | пробовали `frameloop: demand` | откатили (регрессия рендера) | вместо этого — снижение стоимости кадра выше |

Клиентский бандл (production): **1.91 MB** (один чанк; ассеты — статические файлы, не в бандле).

## Проверенный эффект

- Headless-загрузка полного офиса с 3 NPC (Кирилл/Алина/Илья) — GLB парсятся, сцена монтируется, ошибок нет (после уменьшения текстур).
- Все 8 E2E на production-сборке проходят (сцена стабильно грузится и работает).
- Игрок подтвердил устранение `Context Lost` и белого экрана после найма/перехода.

## Найдено, но пока НЕ оптимизировано (рекомендации следующей итерации)

- **Distance-tier обновления NPC** (near/medium/far) — сейчас все NPC обсчитываются одинаково каждый кадр (`useCharacterTransform` + brain). Дальние можно обновлять реже, БЕЗ заморозки-телепортации. Не реализовано.
- **HTML-оверлеи** (подписи NPC, маркеры) — постоянные drei `Html` обновляют DOM-трансформ каждый кадр; при большем числе NPC стоит перейти на in-scene текст/спрайты или скрывать вне frustum агрессивнее. Сейчас скрываются за стенами/дистанцией, но апдейт идёт всегда.
- **Zustand-подписки** — `WorkdayFlowController`, `FreeNpcChatController`, `SprintHud` подписаны на много слайсов (сделано осознанно для реактивности). Профилировать React-commits на реальном GPU; при необходимости — мемоизация производных.
- **Живое FPS/draw-calls профилирование** — требует реального GPU (Open Space / рядом с NPC / у серверной), плюс heap за 20–30 мин. В headless недостоверно.

## Verdict

Подтверждённая крупная проблема (context loss из-за 4K-текстур) **устранена детерминированно и проверяемо** (×16 меньше видеопамяти текстур, ассеты 362→64 MB), плюс снижена стоимость кадра (dpr, тени, AO, споты). Полное FPS-профилирование distance-tier NPC и HTML-оверлеев на реальном GPU — **NOT DONE**, вынесено в рекомендации. По критериям §11 baseline и результат зафиксированы по детерминированным метрикам; живой GPU-замер остаётся открытым пунктом.
