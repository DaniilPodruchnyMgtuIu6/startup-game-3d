# Approval-процесс сгенерированных ассетов

Путь ассета: **draft → review → approved → integrated** (или **rejected** /
**deprecated**). Статусы живут в `generated-asset-register.md`; production-код
может ссылаться только на `approved`/`integrated` ассеты в `public/…`.

## Статусы

- `draft` — кандидат сгенерирован, лежит в `assets/generated/…`;
- `review` — кандидат на художественной приёмке (скриншоты в контексте игры);
- `approved` — принят, пост-обработан, готов к интеграции;
- `rejected` — отклонён; файл остаётся в `assets/generated/` как история и
  НИКОГДА не импортируется кодом (покрыто тестом);
- `integrated` — подключён в production-код (пути в реестре);
- `deprecated` — заменён более новым ассетом; из кода удалён.

## Quality gates (все — до статуса `approved`)

1. **Visual consistency** — соответствие Art Bible: стиль, палитра,
   закреплённая внешность персонажа (identity drift = reject);
2. **Resolution** — не ниже целевой (портрет 768×1024, экран 1376×768) и без
   апскейл-артефактов;
3. **Alpha** — прозрачность только там, где нужна (cutout — через
   `remove_background`), без грязных краёв;
4. **Color space** — sRGB; в Three.js текстуры помечаются `SRGBColorSpace`
   в `OfficeMaterialsProvider`;
5. **Compression** — JPEG q82–86 / PNG только для alpha; UI/текстура ≤ 200 КБ,
   обоснованные исключения фиксируются в реестре;
6. **Texture size** — степень необходимости: экранные текстуры ≤ 1376×768,
   тайлы — POT при необходимости;
7. **Происхождение** — инструмент/модель/промпт записаны в
   `assets/source/prompts/`, строка в реестре, упоминание в `public/CREDITS.md`;
8. **Watermark** — отсутствует;
9. **Identity drift** — лицо/причёска/одежда персонажа совпадают с эталоном;
10. **Реальная необходимость** — ассет закрывает конкретную визуальную дыру,
    а не «просто красивый».

## Художественная приёмка

Скриншот ассета В ИГРЕ (не изолированно) прикладывается к review; финальное
слово — за владельцем проекта. Первый результат генерации не принимается
автоматически: минимум сравнение с эталонами Art Bible.

## Style decision (зафиксировано 2026-07-26)

Рассмотренные направления (по материалам принятой визуальной итерации —
новые генерации отложены из-за баланса в 1 кредит):

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **A. Soft Pixar-like 3D** (эталон — 6 принятых ассетов) | целостность с существующими портретами; тёплый, дружелюбный тон; прощает низкую полигональность сцены | дороже в генерации (identity-референсы) | ✅ **основной** |
| B. Flat vector всё | дёшево, легко в UI | конфликт с 3D-сценой и GLB-персонажами; потеря «кинематографичности» | fallback для плоской графики (постеры/экраны) |
| C. Стилизованный фотореализм | эффектные кадры | смешение стилей запрещено; «зловещая долина»; дороже к производительности | ❌ отклонён |

Офисные направления (тёплый дневной лофт — текущее ✅ / холодный hi-tech ❌
конфликт с тёплой палитрой / тёмный вечерний ❌ читаемость), cinematic
lighting (тёплый ключ + холодная тень ✅ / жёсткий контровой — резерв для
инцидентных сцен), персонажная стилизация (текущая мягкая ✅ / чиби ❌ ломает
серьёзность тем безопасности). Генеративные style boards будут добавлены в
`docs/art/references/` при появлении кредитов — без права менять уже
зафиксированный стиль в одностороннем порядке.
