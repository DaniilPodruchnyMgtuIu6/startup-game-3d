# Scene brief — secret-committed-to-repository

**Аспект безопасности:** секреты в системе контроля версий, разница между удалением из текущей версии, переписыванием истории и настоящей ротацией credential.

**Участники:** Кирилл Морозов (ведёт), Соня Соколова, Алина Белова, Илья Власов (если нанят).

**Локация:** open space, рабочее место Кирилла (тот же экран, что у Feature 19A `supply-chain-update`).

**Завязка:** Кирилл временно вписал API-ключ во внешнюю интеграцию прямо в конфиг, чтобы не останавливать работу, и удалил его новым коммитом. Алина указывает, что старые версии файла всё ещё видны через историю репозитория. Команда должна решить, что делать с ключом, который формально «удалён», но не отозван.

**Тон:** спокойная техническая дискуссия, не паника — важно, чтобы игрок физически понял разницу между «убрать из файла», «убрать из истории» и «сделать ключ недействительным».

**Higgsfield-вставка (опционально, 4–8 сек):**
1. крупный план терминала/diff — строка с ключом подсвечена красным;
2. commit-сообщение "remove temporary key" в git log;
3. курсор наводится на команду `git log -p` — старая версия файла с ключом всё ещё видна;
4. Кирилл смотрит на экран, обеспокоенное выражение;
5. возврат в интерактивную 3D-сцену — **до** выбора.

**Ограничения:** без реальных ключей/токенов/доменов, без показа выбора внутри видео, персонаж соответствует approved identity, одежда/офис совпадают с игрой. Ролик не должен визуально утверждать, что ключ уже украден — только что он технически всё ещё доступен через историю.
