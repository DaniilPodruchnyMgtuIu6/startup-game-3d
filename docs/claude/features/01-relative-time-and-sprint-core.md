# Цель итерации

Добавить детерминированное относительное игровое время и минимальный каркас двухнедельного спринта.

Один спринт состоит из 10 условных рабочих дней.

Игровое время изменяется только после явного подтверждения игрока.

Свободное перемещение, диалоги, осмотр офиса и бездействие не должны менять день.

---

# Что должно появиться в игре

## 1. Состояние спринта

Добавь отдельное состояние спринта.

Рекомендуемый Zustand-store:

`src/game/sprintStore.ts`

Допустимо выбрать другое место, если структура проекта явно требует этого. Выбор необходимо объяснить.

Минимальное состояние:

```ts
type SprintPhase = "planning" | "active" | "review";

type SprintState = {
  sprintNumber: number;
  day: number;
  phase: SprintPhase;
};
```

Начальное состояние новой игры:

```ts
{
  sprintNumber: 1,
  day: 1,
  phase: "planning"
}
```

Добавь действия:

```ts
startSprint(): void;
requestEndDay(): void;
confirmEndDay(): void;
cancelEndDay(): void;
completeSprintReview(): void;
resetSprint(): void;
```

Названия можно изменить только при наличии явной причины.

---

## 2. Чистая логика переходов

Логику перехода между днями нельзя размещать только внутри React-компонента.

Создай чистый модуль правил, например:

`src/game/sprintRules.ts`

Минимальные функции:

```ts
export const SPRINT_DAYS = 10;

export function advanceSprintDay(
  state: SprintState
): SprintState;
```

Правила:

### `planning`

- показывает первый день будущего спринта;
- день равен `1`;
- завершать день нельзя;
- после `startSprint()` фаза становится `active`;
- номер спринта не меняется.

### `active`, дни 1–9

После подтверждения завершения дня:

- день увеличивается на 1;
- фаза остаётся `active`.

### `active`, день 10

После подтверждения завершения дня:

- день остаётся равен `10`;
- фаза становится `review`;
- автоматически начинать следующий спринт нельзя.

### `review`

После `completeSprintReview()`:

- `sprintNumber` увеличивается на 1;
- `day` становится равен `1`;
- `phase` становится `planning`.

### Защитные правила

- день не может стать меньше 1;
- день не может стать больше 10;
- завершение дня запрещено вне `active`;
- повторное подтверждение не должно дважды продвигать день;
- завершение обзора запрещено вне `review`.

Выбери один стиль обработки запрещённых переходов:

- no-op;
- контролируемая ошибка;
- результат с признаком ошибки.

Используй стиль, уже принятый в проекте, и зафиксируй его тестами.

---

## 3. Подтверждение завершения дня

В HUD должна появиться кнопка:

`Завершить рабочий день`

Кнопка доступна только когда:

- фаза игры допускает свободное управление;
- фаза спринта равна `active`;
- не открыта кат-сцена;
- не открыта серверная мини-игра;
- не открыт блокирующий диалог;
- не выполняется действие, которое текущая архитектура считает блокирующим управление.

Не создавай новую глобальную систему блокировок, если существующий код уже умеет определять занятость интерфейса.

После первого нажатия день не меняется.

Открой небольшое подтверждение:

> Завершить рабочий день?

Дополнительный текст:

> После подтверждения игра рассчитает результаты дня. Свободное перемещение и разговоры время не расходуют.

Кнопки:

- `Завершить день`;
- `Отмена`.

Только `Завершить день` вызывает фактический переход.

## 4. Отображение времени

В существующем игровом HUD покажи:

```text
Спринт 1
День 3 из 10
```

Допустим компактный вариант:

```text

```

Во время `planning` дополнительно покажи:

`Планирование`

Во время `review` покажи:

`Итоги спринта`

Не создавай большой новый экран управления спринтом в этой итерации.

## 5. Минимальные оверлеи фаз

### Planning

При новой игре покажи простой блок:

- номер спринта;
- пояснение, что спринт длится 10 условных рабочих дней;
- кнопку `Начать спринт`.

Не добавляй выбор задач. Он относится к отдельной фиче.

После нажатия `Начать спринт`:

- фаза становится `active`;
- игрок возвращается к свободному управлению;
- день остаётся равен 1.

### Review

После завершения 10-го дня покажи простой блок:

- `Спринт N завершён`;
- `Пройдено 10 рабочих дней`;
- кнопку `Перейти к следующему спринту`.

Не добавляй статистику, бюджет и результаты задач. Они появятся позже.

После нажатия:

- номер спринта увеличивается;
- начинается `planning` следующего спринта.

## 6. Сохранение

Состояние спринта должно сохраняться в `localStorage`.

При перезагрузке страницы должны восстанавливаться:

- номер спринта;
- день;
- фаза.

Требования:

- не ломать существующее сохранение `gameStore`;
- не удалять текущие данные игрока;
- корректно обрабатывать отсутствие сохранения;
- корректно обрабатывать старое сохранение, в котором ещё нет состояния спринта;
- некорректные значения должны заменяться безопасными значениями по умолчанию.

Примеры некорректных данных:

- `day: 0`;
- `day: 100`;
- неизвестная фаза;
- отрицательный номер спринта;
- повреждённый JSON.

# Требования к тестам

Добавь unit-тесты для чистой логики.

Минимальный набор:

1. новое состояние соответствует спринту 1, дню 1, `planning`;
2. `startSprint` переводит `planning` в `active`;
3. завершение дней 1–9 увеличивает день;
4. завершение дня 10 переводит игру в `review`;
5. день никогда не становится 11;
6. `completeSprintReview` создаёт следующий `planning`;
7. запрещённые переходы обрабатываются выбранным способом;
8. повреждённое сохранение не ломает приложение;
9. старое сохранение без sprint-state получает начальное состояние;
10. сброс через общую reset-функцию возвращает начальные значения.

Если в проекте есть тестирование Zustand-store, добавь store-тесты.

Не писать хрупкие тесты, завязанные на полный DOM или Three.js-сцену, если достаточно проверить чистую логику.

# Ручной сценарий приёмки

Claude Code должен проверить и описать результат по шагам.

## Сценарий 1. Новая игра

1. Открыть игру с `?intro`.
2. Пройти существующее вступление.
3. Убедиться, что отображается планирование спринта 1.
4. Нажать `Начать спринт`.
5. Убедиться, что HUD показывает `Спринт 1 · День 1/10`.

## Сценарий 2. Время не идёт само

1. Оставить игру открытой.
2. Походить по офису.
3. Поговорить с доступным NPC.
4. Открыть и закрыть доску.
5. Убедиться, что день не изменился.

## Сценарий 3. Завершение дня

1. Нажать `Завершить рабочий день`.
2. Убедиться, что день ещё не изменился.
3. Нажать `Отмена`.
4. Убедиться, что день не изменился.
5. Повторно открыть подтверждение.
6. Нажать `Завершить день`.
7. Убедиться, что HUD показывает день 2.

## Сценарий 4. Завершение спринта

1. Последовательно завершить дни до дня 10.
2. Завершить день 10.
3. Убедиться, что открылись итоги спринта.
4. Убедиться, что день не стал 11.
5. Нажать `Перейти к следующему спринту`.
6. Убедиться, что открыто планирование спринта 2 и день равен 1.

## Сценарий 5. Сохранение

1. Дойти до произвольного дня.
2. Перезагрузить страницу.
3. Убедиться, что номер спринта, день и фаза восстановились.

## Сценарий 6. Сброс

1. Открыть игру с `?intro`.
2. Убедиться, что спринт снова равен 1, день равен 1, фаза `planning`.

# Критерии готовности

Фича считается завершённой только если:

- нет реального таймера игрового времени;
- бездействие не меняет день;
- перемещение не меняет день;
- день меняется только после подтверждения;
- спринт содержит ровно 10 дней;
- после 10-го дня открывается review;
- следующий спринт начинается только по кнопке;
- состояние сохраняется после перезагрузки;
- `?intro` сбрасывает состояние;
- существующий пролог, NPC, навигация и мини-игры продолжают работать;
- тесты проходят;
- production-сборка проходит;
- не реализованы механики следующих этапов.
