# Feature 18 — визуальный production pass с Higgsfield

## Назначение

Feature 18 превращает визуальную часть Startup Office из технического прототипа в цельную стилизованную игру с выразительными персонажами, красивым офисом, качественными анимациями и постановочными сюжетными сценами.

Higgsfield используется только через реально подключённые в проекте инструменты. Claude Code сначала обязан изучить доступные CLI, MCP, API, skills и форматы экспорта, а не придумывать команды или возможности.

Feature 18 не меняет игровую математику, сюжетные choices, последствия Feature 01–17 и условия победы или поражения.

---

Feature 18 выполняется строго по частям:

1. `18a-art-direction-and-higgsfield-workflow.md`;

Claude Code не должен реализовывать следующую часть «заодно».

После каждой части обязательны:

- список созданных и изменённых файлов;
- screenshots или video captures результата;
- узкие тесты;
- полный build;
- проверка производительности;
- ручная художественная приёмка;
- подтверждение пользователя.

---

# Главная цель

Игра должна иметь единый визуальный язык:

- стилизованные, но качественные персонажи;
- одинаковая художественная стилизация во всех ассетах;
- живые эмоции, взгляд и жесты;
- естественные анимации работы и общения;
- сюжетные сцены с камерой на уровне персонажей;
- крупные, средние, over-the-shoulder и reaction shots;
- красивый, наполненный, но не перегруженный офис;
- понятные световые состояния событий;
- отсутствие постоянной верхней камеры в диалогах;
- стабильная производительность.

---

# Роль Higgsfield

Higgsfield разрешено использовать для:

- character concept sheets;
- consistent character references;
- turnaround и expression sheets;
- pose и motion references;
- storyboard и keyframes;
- camera и lighting references;
- office moodboards;
- posters, decals и экранный контент;
- заранее отрендеренных вставок, если они действительно уместны;
- upscale/background removal при наличии таких инструментов.

Higgsfield не заменяет:

- рабочий 3D rig;
- skeleton;
- animation clips;
- Three.js camera;
- interactive scene;
- игровую логику;
- NPC planner;
- state machine.

Generated изображение или видео считается только референсом, пока оно реально не встроено в production path проекта.

# Запрещено

- менять лица персонажей между сценами;
- смешивать фотореализм и стилизованные модели;
- импортировать огромные несжатые ассеты;
- использовать случайный первый результат генерации;
- заменять интерактивную 3D-игру набором MP4;
- делать всю режиссуру одной верхней камерой;
- добавлять новые сюжетные решения;
- менять баланс и последствия;
- создавать неподдерживаемые rigged-модели;
- коммитить ключи Higgsfield;
- печатать секреты в логах;
- выполнять `git push`.

---

# Общий критерий завершения

Feature 18 завершена только если:

- есть утверждённая Art Bible;
- персонажи визуально стабильны;
- модели подходят для крупных планов;
- основные анимации не выглядят как placeholders;
- существует единый animation state machine;
- сюжетные сцены используют профессиональный camera language;
- офис имеет цельные материалы и освещение;
- ключевые сцены поставлены и встроены;
- generated assets оптимизированы;
- visual regression и cinematic tests проходят;
- performance budget соблюдён;
- production build проходит.
