Порядок разработки Startup Office вместе с Claude Code

Цель этого набора

Не передавать Claude Code весь сценарий игры одним большим запросом.

Каждая игровая механика реализуется отдельной итерацией:

передать Claude Code только один файл фичи;

дать ему изучить актуальный код проекта;

реализовать только указанную фичу;

проверить приложение и тесты;

вручную принять результат;

только после этого переходить к следующему файлу.

Claude Code не должен заранее реализовывать механики из следующих этапов.

Зафиксированные технические принципы

Проект уже использует:

React 19;

TypeScript;

Vite;

@react-three/fiber;

Three.js;

Zustand;

Vitest;

localStorage для сохранения прогресса.

При реализации новых фич необходимо соблюдать существующие правила проекта:

KISS;

без преждевременных абстракций;

без заглушек, которые изображают несуществующий геймплей;

игровую логику держать отдельно от React-компонентов;

React-компоненты должны отображать состояние и вызывать действия;

не выполнять широкий рефакторинг файлов, не связанных с текущей фичей;

не менять визуальный стиль существующего интерфейса без необходимости;

сохранять обратную совместимость с существующим прогрессом в localStorage;

после каждой итерации запускать тесты и production-сборку.

Обязательный формат работы Claude Code на каждой итерации

Перед изменением кода Claude Code должен:

прочитать AGENTS.md;

изучить структуру src;

найти существующие Zustand-сторы;

найти текущий игровой HUD;

найти код сброса прогресса через ?intro;

перечислить файлы, которые планирует изменить;

убедиться, что задача не дублирует существующую механику.

После реализации Claude Code должен вернуть:

краткое описание результата;

полный список созданных и изменённых файлов;

объяснение каждого изменения;

команды, которые были выполнены;

результаты тестов;

результат production-сборки;

ручной сценарий проверки;

известные ограничения текущей итерации.

Запрещено на любой итерации

Claude Code не должен:

реализовывать следующую фичу «заодно»;

добавлять бюджет, аудит, найм или поражения, если этого нет в текущем файле;

создавать универсальный event engine до появления нескольких реальных сценариев;

подключать DeepSeek до завершения детерминированного игрового ядра;

хранить LLM API-ключи в клиентском коде, Markdown, Git или переменных VITE_*;

делать игровую математику зависимой от ответов языковой модели;

использовать реальное время браузера для движения игрового времени;

заставлять игрока проигрывать из-за того, что он долго ходил по офису;

добавлять внешнего консультанта по безопасности;

создавать 3D-модель CEO;

переписывать работающую навигацию, анимации или серверные мини-игры без прямой необходимости.

Правило перехода к следующей фиче

Следующая фича не начинается, пока текущая не соответствует всем условиям:

приложение запускается;

production-сборка проходит;

тесты проходят;

ручной сценарий проверки выполнен;

сохранение и сброс прогресса работают;

в код не попали механики следующих этапов;

пользователь подтвердил результат.

На текущем этапе Claude Code нужно передать только:

17a-story-core-and-balance-config.md

Feature 17: обязательное дробление

Feature 17 выполняется тремя отдельными частями:

17a-story-core-and-balance-config.md;

17b-security-and-role-decision-scenes.md;

17c-level1-checkpoints-consequences-and-testing.md.

Claude Code не должен реализовывать 17B до успешной проверки 17A и не должен реализовывать 17C до успешной проверки 17B.
