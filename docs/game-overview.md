# Startup Office — обзор реализованных механик

Документ описывает **текущее состояние** игры: что уже реализовано (механики, сцены,
челленджи), какие есть точки расширения (хуки/заготовки) и чего пока **нет**. Цель —
дать полную картину для проектирования сценария игры.

> Игра — 3D-«песочница» офиса стартапа с изометрической камерой. Игрок — новый
> руководитель отдела. Пока это скорее «движок + пролог + первые механики», чем
> законченный сюжет: есть вступление, знакомство с командой (1 персонаж),
> обучающие мини-игры по безопасности серверов и одна кат-сцена. Экономики,
> прогрессии, концовок (кроме отказа от работы) — ещё нет.

---

## 1. Технологии и принципы

- **Стек:** React 19, `@react-three/fiber` 9, `three` 0.185, `@react-three/drei` 10,
  `zustand` 5 (стейт-сторы), TypeScript, Vite 8, Vitest (+ `@react-three/test-renderer`).
- **Пост-обработка:** N8AO (ambient occlusion), Bloom, Vignette, ACES-тонмаппинг.
- **Бэкенда нет.** Всё в браузере. Прогресс сохраняется в `localStorage`.
- **Язык контента:** русский (диалоги, задачи, UI).
- **Принципы проекта (`AGENTS.md`):** KISS, без «мок-фич», экономный код. Проверка
  фич — прогоном приложения; логика вынесена в чистые модули отдельно от React.

---

## 2. Мир и сцена

**Здание** — прямоугольник 24×16 юнитов, стены 2.8 м высотой, с «срезом» верхней
части для изометрического обзора. Планировка — 7 комнат:

| Колонка | Комнаты (сверху вниз по Z) |
|---|---|
| Левая | Переговорная, Focus-комната, **Серверная** |
| Центр | **Open Space** (общий зал) |
| Правая | **Кабинет CEO**, Кухня, Игровая |

Комнаты разделены стеклянными перегородками с дверными проёмами; навигация знает про
проёмы и обходит стены/мебель.

**Камера:** ортографическая изометрическая, свободный орбит/пан/зум (`CameraControls`),
ограничена габаритами здания. Отдельная **перспективная кат-сцен-камера** подменяет
основную на время кат-сцен (для «киношных» ракурсов) и возвращает управление после.

### Что стоит в комнатах (интерактив выделен **жирным**)

- **Open Space:** 4 кластера по 4 **рабочих места** (стол+стул+монитор), диван, кофейный столик, растения, трек-светильники.
- **Кабинет CEO:** **стол CEO**, **капитанское кресло** (можно сесть), книжный шкаф, **диван**, кофейный столик, растение.
- **Серверная:** 4 **серверные стойки** (см. §9), дверь, кабель-канал, бетонный пол.
- **Переговорная:** стол, 8 **стульев** (можно сесть), ТВ-панель, **вайтборд** (открывает доску задач).
- **Focus-комната:** 2 **рабочих места**.
- **Кухня:** остров, **кофемашина** (сварить кофе), барные стулья, холодильник.
- **Игровая:** пинг-понг-стол, турник, **диван**, книжный шкаф.

## 3. Персонаж игрока и система движения

Игрок управляет одним персонажем — **«Основатель / Руководитель отдела»** (бизнесмен
в костюме). Спавн в открытом зале. Управление — **клик по полу/объекту** («point &
click»): персонаж прокладывает путь и идёт.

**Машина состояний персонажа** (одна и та же для игрока и NPC):
`idle` → `walking` → и целевые состояния:
- `sittingDown` → `working` (печатает за рабочим местом; монитор «загорается»)
- `brewingCoffee` → `drinkingCoffee` (в руке появляется кружка)
- `sittingIdle` (сидит на стуле/в кресле), `sofaSitting` (на диване)
- `repairing` (чинит сервер — открывает мини-игру, см. §9)
- `talking`, `looking` (позы для диалогов/кат-сцен)

**Навигация:** A\* по сетке 0.2 м. Учитывает: клиренс у стен, габариты мебели
(footprint регистрируется автоматически при рендере), дверные проёмы, и **направление
захода/схода** с сидений (персонаж садится «спереди», встаёт «вперёд», не сквозь
спинку). Клик по стене/мебели «прилипает» к ближайшей проходимой клетке.

**Анимации** (Mixamo-клипы, свои для каждого персонажа): `idle, walk, sit, type,
drink, sitIdle, sofaSit, talk, look`. Есть цепочка фолбэков (если клипа нет — берётся
ближайшая поза). Скорость проигрывания ходьбы синхронизирована с реальной скоростью
перемещения (ноги не «скользят»), с корректировкой высоты (`walkLift`), чтобы ступни
не проваливались в пол.

## 4. NPC и «жизнь офиса»

Все ходячие тела (игрок и NPC) живут в одном сторе и делят одну машину состояний и
навигацию. **Автономные NPC** сами планируют «офисную жизнь».

**Планировщик активностей** (чистая, детерминированная логика на сид-RNG) выбирает по
весам: `work` (0.5) / `coffee` (0.15) / `meeting` (0.13) / `sofa` (0.12) / `wander`
(0.1), с длительностью пребывания на каждую активность. Перерывы не повторяются
подряд. «Claims» (заявки) не дают двум персонажам занять одно место.

- **Сейчас автономный NPC один — продакт-менеджер Соня Соколова** (29, «организованная,
  прямолинейная, болеет за продукт»). Спавнится в общем зале, живёт по планировщику
  после пролога.
- **Хук под ИИ-мозги:** у каждого NPC есть поле `npc.planActivity` — контракт
  планировщика можно заменить на асинхронный «ИИ-агент», получающий на вход `persona`
  персонажа. **Пока не реализовано** (используется случайный планировщик); персоны
  описаны как будущая форма промпта.

## 5. Система взаимодействий

Интерактивные объекты вешают невидимые «триггеры», которые регистрируются в живом
реестре по типам: `workstation`, `coffee`, `seat`, `sofa`, `server`.

- **Наведение** мышью → белый контур-силуэт объекта (по запросу пользователя контур
  теперь только на hover, не постоянный).
- **Клик** → соответствующее действие (сесть/сварить кофе/чинить и т.д.); персонаж сам
  доходит до места.
- NPC **автоматически видят** новые интерактивные объекты через тот же реестр — новая
  мебель сразу становится «доступной» для их поведения.

## 6. Игровой поток и фазы

Фаза хранится в `gameStore` и сохраняется в `localStorage`
(`playerName`, `phase`, `tasks`, `reprimands`). Параметр URL `?intro` сбрасывает прогресс.

```
intro ──accept──> meetPm ──(поговорил с PM)──> free
  │
  └──refuse──> fired (game over, рестарт)
```

1. **`intro` — вступление (оверлей поверх сцены):**
   - Разгневанный **председатель совета директоров** отчитывает игрока: прошлый
     руководитель провалил сроки, продукт застрял, команда разбежалась.
   - Ставит задачу: наладить процессы, собрать команду, довести продукт до релиза.
   - Выбор: **согласиться** (→ ввод имени → фаза `meetPm`) или **отказаться**
     (→ `fired`, «Вы уволены», рестарт).

2. **`meetPm` — знакомство с командой:**
   - Над PM висит индикатор 💬; клик — игрок подходит, при сближении открывается её
     вступительный диалог (продукт в хаосе, нужны люди — «готовьтесь собирать команду»).
   - По завершении диалога — фаза `free`, NPC начинают автономную жизнь.

3. **`free` — свободная игра:** открытый офис, все интерактивы доступны, NPC живут сами.

**Концовок пока нет**, кроме тупиковой `fired` (отказ). «Победы»/релиза продукта —
нет.

## 7. Диалоги и выборы

- **Диалоговая панель** (снизу): по одной реплике, с именем/ролью/портретом говорящего
  и кнопкой «Далее». У последней реплики можно задать свою подпись кнопки.
- **Выбор (choice):** панель показывает кнопку на каждый вариант; возвращает id выбора.
  Используется в кат-сценах для развилок.
- Портреты — нарисованные изображения (у игрока, PM, босса, охраны — с разными
  эмоциями: злой/шокирован/грустный/думает/нейтрально).

## 8. Доска задач

- В переговорной есть **вайтборд** — клик открывает оверлей со списком TODO отдела.
- Стартовая задача: **«Сформировать команду»**.
- Задачи можно добавлять в рантайме (например, кат-сцена добавляет «Проводить курсы по
  безопасности (регулярно)»).
- **Механики выполнения задач как таковой нет** — это пока просто отображаемый список
  (галочка `done` в данных есть, но геймплейного способа закрывать задачи нет).

**Счётчик «выговоров» (`reprimands`):** увеличивается при некоторых выборах (напр.,
свалить вину на PM). Сохраняется. **Пока ни на что не влияет** — задел под последствия.

## 9. Челлендж: мини-игры по безопасности серверов

Главная реализованная геймплейная механика (кроме пролога). В **Серверной** 4 стойки,
каждая **жёстко привязана к роли** и своей мини-игре:

| Стойка | Роль | Табличка | Мини-игра |
|---|---|---|---|
| 0 | gateway | GATE | Фаервол |
| 1 | auth | AUTH | Логи |
| 2 | database | DB | SQL-инъекция |
| 3 | backup | BKP | — (резерв, **не ломается**) |

**Событие поломки:** стойка «ломается» → все её LED мигают **красным**, табличка
краснеет, над стойкой всплывает **восклицательный знак «!»** (билборд к камере,
покачивается) — сигнал «подойди и почини». Контур белым — только при наведении.
Сломанная стойка кликабельна.

**Поток починки:** клик по сломанной стойке → персонаж идёт к ней через обычную
навигацию → по прибытии (состояние `repairing`) открывается **оверлей мини-игры**.
Победа → стойка «зеленеет», инцидент закрывается. Провал → можно повторить (даётся,
возможно, другой сценарий из пула). Выход крестиком → стойка остаётся сломанной.

**Три мини-игры** (каждая — интерактивный сценарий, а не квиз; у каждой пул
рукописных сценариев и финальный экран с 2-3 «выводами»):

1. **Фаервол (GATE).** Список портов сервера (SSH/HTTP/HTTPS/MySQL/FTP/…), игрок
   открывает/закрывает их, затем «запускает трафик». Легитимный запрос на закрытый
   порт роняет uptime; атака на открытый порт — это «взлом». Победа: 0 взломов +
   uptime выше порога. **Учит:** принцип «default-deny», не выставлять БД наружу,
   закрывать легаси-протоколы. 3 сценария.
2. **Логи (AUTH).** Прокручиваемый auth-лог; игрок отмечает подозрительные строки и
   банит IP атакующего. Победа: отмечены все улики + забанен верный IP. **Учит:**
   как выглядит брутфорс/кража сессии/инсайдер в логах. 3 сценария.
3. **SQL-инъекция (DB), две фазы.** Сначала игрок **сам взламывает** форму логина
   (`' OR '1'='1' --`), видит утечку таблицы; затем **чинит** — выносит ввод в
   параметр (`WHERE login = ?`), и та же атака больше не проходит. **Учит:** почему
   склейка строк опасна и как параметризация лечит инъекции. 2 сценария.

**Инцидентная история (важный хук):** по каждому инциденту пишутся `brokenAt`,
`fixedAt`, число провалов. Это **задел под будущие последствия**: система штрафов
(за долгий простой сервера / повторные провалы, влияющие на исход игры) сможет
подписаться на историю **без изменения механики**. **Сейчас штрафов нет.**

## 10. Система кат-сцен

Кат-сцены — это **скрипты-асинхронные функции**, дирижирующие сценой через
**Director API**:

- `walk`, `face`, `sit`, `look`, `talk` — управление телами (реальные модели или
  плейсхолдер-коробки);
- `camera` — перспективный «облёт»/наведение;
- `say` — диалог, `choice` — развилка;
- `spawnActor` / `spawnModeledActor` / `despawnActor` — временные актёры сцены;
- `wait`, `addTask`.

На время кат-сцены блокируется ввод игрока, ставятся на паузу «мозги» указанных NPC,
подменяется камера. **Реестр сцен**, запуск — `window.__startCutscene(id)` (dev).
**Реальных триггеров-условий пока нет** (запуск ручной).

**Единственная готовая кат-сцена — `security-breach`:**
- PM уходит с рабочего места, **не заблокировав компьютер** (монитор остаётся гореть).
- Появляются **два аудитора безопасности** (Максим Орлов, Дмитрий Воронин), осматривают
  место, идут в кабинет CEO и предъявляют игроку нарушение политики безопасности.
- **Развилка (1 выбор):** «беру ответственность» / «это недосмотр PM». Свалить вину →
  +1 выговор.
- Обе ветки заканчиваются одинаково: на отдел накладывают обязанность **регулярно
  проводить курсы по безопасности** (в доску задач добавляется соответствующая задача).
- Полноценные портреты с эмоциями по ходу эскалации.

Смысл сцены — сюжетно мотивировать мини-игры по безопасности (см. §9).

## 11. Консольные триггеры (dev-режим)

Доступны только при `npm run dev`, в консоли браузера:

```js
// Поломка серверов → открывает соответствующую мини-игру после клика по стойке
window.__breakServer()            // случайная здоровая стойка (кроме backup)
window.__breakServer('gateway')   // GATE → Фаервол
window.__breakServer('auth')      // AUTH → Логи
window.__breakServer('database')  // DB   → SQL-инъекция
window.__breakServer('backup')    // no-op (резерв, не ломается)

// Кат-сцены
window.__startCutscene('security-breach')   // сцена с аудитом безопасности

// Инспекция состояния серверов
const si = (await import('/src/game/serverIncidentsStore.ts')).useServerIncidentsStore.getState()
si.racks     // статусы всех стоек
si.history   // закрытые инциденты (задел под штрафы)
```

Также `?intro` в URL сбрасывает сохранённый прогресс (переиграть вступление).

## 12. Чего пока НЕТ (важно для сценария)

Это открытые направления — то, вокруг чего можно строить сюжет и механики:

- **Экономика / деньги / ресурсы** — отсутствуют.
- **Время суток / расписание / дедлайны** — отсутствуют.
- **Прогрессия продукта / «релиз»** — нет; задача «довести продукт до релиза» пока
  только в тексте пролога.
- **Наём и управление командой** — задача «Собрать команду» есть, но **механики найма
  нет**; автономный NPC пока один (PM). Охранники — только актёры кат-сцены.
- **Выполнение задач с доски** — нет геймплейного способа закрывать задачи.
- **Последствия/штрафы** — `reprimands` и история инцидентов **накапливаются, но ни на
  что не влияют** (готовый хук под концовки/санкции).
- **Концовки** — только тупиковая `fired` (отказ во вступлении). Победы/поражения по
  ходу игры нет.
- **ИИ-мозги NPC** — хук есть, реализации нет (NPC живут по случайному планировщику).
- **Триггеры кат-сцен** — только ручной dev-запуск; авто-условий (по времени/событиям)
  нет.
- **Прочие мини-игры/челленджи** — кроме трёх серверных, других нет; зарезервированы
  4-я серверная роль (`backup`) и слот под 4-ю мини-игру.
- Нет инвентаря, крафта, боёв, экрана характеристик — это чистый «нарратив + мини-игры».

## 13. Готовые точки расширения (хуки)

Куда «подключаться» новым механикам без переписывания:

- **Новая кат-сцена:** добавить скрипт в реестр сцен; Director API уже покрывает
  ходьбу/камеру/диалоги/выборы/актёров/задачи.
- **Триггер кат-сцены/поломки по условию:** вызвать `startScene(id)` / `breakServer()`
  из места, где детектится условие (таймер, выполненная задача, фаза).
- **Последствия:** подписаться на `serverIncidentsStore.history` и `reprimands` →
  выговоры/провалы/простой → концовка или санкции (существующий `addReprimand`).
- **4-я мини-игра:** роль `backup` зарезервирована; нужен модуль игры + запись в реестр.
- **ИИ-NPC:** реализовать `planActivity` как ИИ-агента с персоной; новые NPC —
  добавить определение персонажа (модель/клипы/persona) в ростер.
- **Новые интерактивы:** новый триггер с `kind` → автоматически видят и игрок, и NPC.

### Резюме одним абзацем

Есть работающий 3D-офис с изометрической камерой, полноценной навигацией и анимациями,
пролог (совет директоров → знакомство с PM), система диалогов/выборов, доска задач,
одна сюжетная кат-сцена (аудит безопасности) и три обучающие мини-игры по безопасности
серверов с системой поломок и инцидентной историей. Экономики, прогрессии продукта,
найма команды, последствий и концовок пока нет — это и есть основное пространство для
сценария. Ключевые заготовки под сюжет уже стоят: фазы игры, счётчик выговоров, история
инцидентов, реестр кат-сцен и хук под ИИ-поведение NPC.
```
